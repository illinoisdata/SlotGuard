## Credential Benchmark — FPS + SEG (Paper Table 2)

- Sessions: **200**, planted credentials: **852**

Leakage metrics measure what survives the sanitizer in the upstream payload. The rightmost column is a **structural proxy** for task recoverability — see the caveat block under the table.

| Method | Session leak ↓ | Credential leak ↓ | Categorical leak ↓ | Anchor preservation ↑ (proxy) |
|---|---|---|---|---|
| none | 100.0% | 100.0% (852/852) | 0.0% | 100.0% |
| pattern_placeholder | 100.0% | 23.5% (200/852) | 100.0% | 100.0% |
| fps_only | 100.0% | 23.5% (200/852) | 0.0% | 100.0% |
| fps_with_seg | 0.0% | 0.0% (0/852) | 0.0% | 100.0% |

**How to read the table.** *Session leak* counts a session as leaked if any of its planted credentials survives in the upstream payload — a binary metric per session, so it saturates whenever even one credential class slips through. *Credential leak* is the per-credential rate over all planted values and shows that pattern-only and FPS-only both miss exactly the "split" exposure (~25% of credentials), while FPS+SEG closes that gap. *Categorical leak* counts sessions whose payload contains a typed `__CATEGORY_n__` placeholder — pattern-only inevitably leaks the category of every value, FPS does not.

> ⚠️ **What "Anchor preservation" is and is NOT.**
> 
> **Is:** a *structural* proxy. Each synthesized session declares a small set of "task anchor" tokens (function/symbol names like `AuthMiddleware`, `parse_token`) that a downstream LLM would need to refer to. We mark a session as preserved if **every anchor token still appears verbatim** in the sanitized payload after the four conditions run. The metric is computed without ever invoking an LLM.
> 
> **Is NOT:** real task success. Whether the model can actually solve the user's coding task on the sanitized payload is a separate experiment (Experiment 4, the live workflow probe against a local or remote OpenAI-compatible endpoint). The paper-style success-rate numbers belong to that live-model evaluation and are **not comparable** to the column above.
> 
> **Why the proxy is 100% across all four conditions in this run:** the anchor tokens in the synthesized corpus are deliberately disjoint from any credential value, so no sanitizer (including the over-eager pattern_placeholder) can mangle them. This shows that the sanitizer does not destroy LLM-relevant structural anchors — a necessary condition for task recoverability, not a sufficient one. To stress-test sufficiency, see the live-model probe.
